# Ритм сбора (crawl cadence)

Состояние на **2026-10-08**. Ежедневный лёгкий сбор — команда `light-day`. Полный `ensure-ready` остаётся редкой сверкой сделок.

## SLA сигналов

| Сигнал | Оперативность |
|--------|----------------|
| Новые объекты / уценки | желательно день в день (лёгкий прогон) |
| Гипотезы сделок (`likely_deal`) | **не день сделки**; достаточно узнать **в течение месяца** |
| Явные sold/rented с площадки | как появятся в crawl |

Полный ежедневный `ensure-ready` (fill + reconcile всех источников по десяткам страниц) занимает **часы** из‑за глубины пагинации, rate-limit и нестабильности OLX — это disproportionate для SLA «сделка ≤ месяц».

## Как устроено

**Гибрид:**

1. **Ежедневно лёгкий** — `python -m scripts.cli light-day`. До 6 страниц ленты, стоп когда страница без новых id, детали только у новых и изменённых (потолок 30 на источник). Площадки параллельно. Vanish нет.
2. **Реже полный reconcile** — `ensure-ready` раз в несколько дней или раз в неделю. Vanish и сделки с лагом дней–пары недель, внутри месяца. Добор страниц останавливается, если уникальных id не стало больше (`seen_plateau`). Любая лента останавливается после двух страниц подряд без новых id.

Альтернативы на будущее: добор только хвоста страниц, не с первой; точечные проверки «ещё жив?» по активным ID.

## Чего не делать

- Не снижать пороги `MIN_SEEN` / vanish ratio «чтобы быстрее» без явного решения и теста.
- Не считать сырое «сняты с площадок» сделками.
- Не обещать day-1 vanish при лёгком ежедневном режиме.

## Текущая операционка

Триггер «ежедневное обновление» = `serve` → `light-day` → `repair-spaced-prices` → проверка новых и уценок.  
`ensure-ready` — не каждый день. При зависании лога >1–2 ч без прогресса процесс убивать и перезапускать точечно.
