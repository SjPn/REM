# Ритм сбора (crawl cadence)

Состояние на **2026-10-12**. Ежедневный прогон — `probe-day` (до 40 минут). `light-day` остаётся урезанным верхом ленты. Полный `ensure-ready` — редкая сверка, не каждый день.

## SLA сигналов

| Сигнал | Оперативность |
|--------|----------------|
| Новые объекты / уценки с верха ленты | в прогоне `probe-day` |
| Уценка старого объявления | в день прямой проверки карточки (круг в несколько дней) |
| Гипотезы сделок (`likely_deal`) | **не день сделки**; достаточно узнать **в течение месяца** |
| Явные sold/rented с площадки | как появятся в crawl |

Полный ежедневный `ensure-ready` (fill + reconcile всех источников по десяткам страниц) занимает **часы** из‑за глубины пагинации, rate-limit и нестабильности OLX — это disproportionate для SLA «сделка ≤ месяц».

## Как устроено

**Ежедневно `probe-day`** — `python -m scripts.cli probe-day`. Общий лимит **40 минут**, площадки параллельно. Два шага:

1. **Голова ленты.** До 8 страниц на ленту, стоп после двух страниц подряд без новых id. Детали только у новых и изменённых (потолок 30 на источник). Отсюда новые объекты и уценки, которые площадка подняла наверх.
2. **Прямая проверка хвоста.** Активные карточки, которых не было в голове, открываются своим URL, сначала самые давно не проверенные. Живая страница обновляет цену. «Продано» / «сдано» на странице пишется сразу. Ответ «снято» (404/410 или шаблон снятия) — один промах; гипотеза сделки только со второго такого ответа **в другой день**. Таймаут и бан промахом не считаются: площадка на этот прогон останавливается.

Полный круг хвоста занимает несколько дней и остаётся внутри месячного SLA сделок. Все активные URL за один день не открываются.

`light-day` — только шаг 1, без проверок карточек и без сделок.

**Редкий `ensure-ready`** по-прежнему листает ленту вглубь до coverage и делает vanish по «не увидели в ленте». Его не запускать параллельно с `probe-day`. Для ежедневного обновления он не нужен.

## Чего не делать

- Не снижать пороги `MIN_SEEN` / vanish ratio «чтобы быстрее» без явного решения и теста.
- Не считать сырое «сняты с площадок» сделками.
- Не обещать day-1 vanish при лёгком ежедневном режиме.

## Текущая операционка

Триггер «ежедневное обновление» = `serve` → `probe-day` → `repair-spaced-prices` → проверка новых и уценок.  
`ensure-ready` — не каждый день. При зависании лога >1–2 ч без прогресса процесс убивать и перезапускать точечно.
