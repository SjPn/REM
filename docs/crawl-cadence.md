# Ритм сбора (crawl cadence)

Состояние на **2026-09-23**. Код режима «быстрый день» ещё **не внедрён** — зафиксировано решение по продукту.

## SLA сигналов

| Сигнал | Оперативность |
|--------|----------------|
| Новые объекты / уценки | желательно день в день (лёгкий прогон) |
| Гипотезы сделок (`likely_deal`) | **не день сделки**; достаточно узнать **в течение месяца** |
| Явные sold/rented с площадки | как появятся в crawl |

Полный ежедневный `ensure-ready` (fill + reconcile всех источников по десяткам страниц) занимает **часы** из‑за глубины пагинации, rate-limit и нестабильности OLX — это disproportionate для SLA «сделка ≤ месяц».

## Согласованное направление (без кода пока)

**Гибрид:**

1. **Ежедневно лёгкий** — верх выдачи по новизне (порядка 4–8 страниц / источник) → новые и уценки.
2. **Реже полный / скользящий reconcile** — раз в несколько дней или раз в неделю → vanish и сделки с лагом дней–пары недель, но стабильно внутри месяца.

Альтернативы на будущее: скользящие окна страниц; watchlist точечных проверок «ещё жив?» по активным ID; ротация источников по дням недели.

## Чего не делать

- Не снижать пороги `MIN_SEEN` / vanish ratio «чтобы быстрее» без явного решения и теста.
- Не считать сырое «сняты с площадок» сделками.
- Не обещать day-1 vanish при лёгком ежедневном режиме.

## Текущая операционка (пока код старый)

Триггер «ежедневное обновление» всё ещё = `serve` → `ensure-ready` до 5/5 → `repair-spaced-prices` → проверка.  
OLX часто ломает 5/5 (таймауты страниц); добор `--sources olx --page-ceiling 80..120` может идти часами — при зависании лога >1–2 ч без прогресса процесс убивать и перезапускать точечно.
